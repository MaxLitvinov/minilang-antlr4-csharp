# MiniLang: інтерпретатор на ANTLR4 і C#

Навчальний проєкт: граматика простої мови програмування **MiniLang** у нотації ANTLR4, лексер і парсер, згенеровані для C#, та інтерпретатор на основі шаблону Visitor.

## Можливості мови

- змінні: `let x = 5;` і присвоєння `x = x + 1;`
- вивід: `print(x);`
- умови: `if (...) ... else ...`
- цикли: `while (...) ...`
- блоки: `{ ... }`
- арифметика `+ - * / %`, унарний мінус, дужки
- порівняння `< <= > >= == !=`
- числа, рядки (з конкатенацією через `+`), коментарі `// ...`

## Приклад

```
// факторіал 5
let n = 5;
let f = 1;
while (n > 1) {
    f = f * n;
    n = n - 1;
}
print("5! = " + f);
```

Результат: `5! = 120`

## Структура проєкту

| Файл / папка | Призначення |
|---|---|
| `MiniLang.g4` | граматика мови в нотації ANTLR4 |
| `Generated/` | згенеровані лексер, парсер і візитор |
| `Program.cs` | запуск лексера й парсера, обробка синтаксичних помилок |
| `EvalVisitor.cs` | інтерпретатор (Visitor), семантичні перевірки |
| `tests/` | тестові програми `.ml` |

## Середовище

- Windows, .NET SDK 8
- ANTLR 4.13.1 (`pip install antlr4-tools`; потребує Java)
- NuGet-пакет `Antlr4.Runtime.Standard` 4.13.1

Версії генератора й runtime мають збігатися.

## Генерація аналізатора

```
antlr4 -v 4.13.1 -Dlanguage=CSharp -visitor -no-listener -package MiniLangApp -o Generated MiniLang.g4
```

## Запуск

```
dotnet build
dotnet run -- tests\ok_factorial.ml
dotnet run -- tests\ok_factorial.ml --tree
```

Ключ `--tree` додатково виводить дерево розбору.

## Тестування

| Тест | Очікуваний результат |
|---|---|
| `ok_factorial.ml` | `5! = 120` і `OK` |
| `err_syntax.ml` (`let x = ;`) | `line 1:8 mismatched input ';' ...` і «Знайдено синтаксичних помилок: 1» |
| `err_undeclared.ml` (`y = 3;`) | «Помилка виконання: Змінну 'y' не оголошено (рядок 1)» |

Синтаксичні помилки виявляє парсер ANTLR, семантичні (необ'явлена змінна, ділення на нуль) перевіряє візитор.

## Висновки

- ANTLR4 генерує лексер і парсер з декларативного опису граматики.
- Ліву рекурсію та пріоритет операторів ANTLR обробляє автоматично.
- Visitor відокремлює логіку виконання від граматики.
- Недоліки: потрібна Java для генерації, версії генератора й runtime мають збігатися.
